# APA 架构审计与规范化实施计划

**目标：**审计整个现有应用，落实设备身份、采样数据及云端历史边界，补关键测试，形成可维护的 README、ROADMAP、架构与技术债文档。

**方案：**沿用单 app 模块，提取纯 Kotlin 领域模型和策略；Android 采集器负责读取，解析器负责验证，展示层负责文本。保留既有 UI/键盘修复，不做大规模页面重写。

**约束：**Android API 26+；不增加网络权限、不上传用户文件、不读取密钥内容、不发布版本、不覆盖手机。模型名称保持现有配置，不宣称已验证外部可用性。

## 执行顺序与验收

- [x] 基线：读取所有生产层、现有测试、Manifest/Gradle/说明文档；执行 testDebugUnitTest、lintDebug，记录范围和限制。
- [x] 设备身份：新增原始 manufacturer/model/device/brand、展示名和来源枚举；查表用 Locale.ROOT，覆盖缺失、大小写、错误厂商、离线库失败；接入设备采集和档案输出。保留系统原值，未知机型不猜商品名。
- [x] 数据边界：设备快照移出 Activity；采样时间使用 Instant，格式化仅在展示边界；根电池循环计数使用 Long?；无效资源数据不得被本地规则评价为正常。
- [x] Scene：先增加失败用例（单位混淆、异常百分比、充电区间），再修数值解析与摘要；限制输入大小，拒绝异常 CSV 结构并保留用户可理解的错误。
- [x] 对话：用类型表达本地/云端历史范围及服务商归属，纯策略过滤历史并由实际请求使用；测试本地 Scene 摘要、切换服务商、无效角色、历史窗口。
- [x] 测试维护：更新失效 UI 测试入口、预览包名和输入框选择器；不调用真实模型、不改用户凭据。
- [x] 文档：README 中英同步当前源码与发布版区别；新增 ARCHITECTURE、DATA_MODEL、TECH_DEBT、ROADMAP、TESTING，列出证据、优先级、验收条件和未测项。
- [x] 验证：执行全部 JVM 测试、Debug/Release Lint、Debug 构建和 androidTest 编译；检查 diff、测试数量与失败数；有可用测试设备才运行仪器测试。独立审查后修复发现的问题。

## 选择理由

只写报告无法阻止已发现的数据边界回归；一次性多模块/ViewModel 重写风险和验证成本过大。本轮采用可测试的渐进提取，保留大型 UI 拆分、网络适配层与跨机型实测等明确技术债。

完成记录：75 项 JVM 测试通过；Debug/Release Lint 各 23 warnings、0 errors。用户随后连接手机执行仪器测试，最新结果仍需收尾，不能声称最终实机全通过。详细证据见 docs/TESTING.md。
