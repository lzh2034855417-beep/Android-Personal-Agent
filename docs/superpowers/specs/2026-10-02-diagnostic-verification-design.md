# 诊断 → 调整 → 复测：第一版设计

日期：2026-10-02。代码基线：`558d859`。状态：设计已确认，任务 1–7 已在实施分支落地，最终独立审查与主项目同步由控制者执行。合成 JVM 测试、APK 构建与仪器测试编译完成；设备运行、真实 OEM 窗口兼容和真实模型评测待另行授权验证。本文定义设计契约，不代替测试证据（见 `docs/TESTING.md`）。

## 1. 目标与已确认范围

用户希望 APA 获得能改变核心用法的能力，而不是继续微调回答文案。已确认方向：用户保存调整前的诊断，记录一项手动调整与原设置，再导入或采集复测证据，查看变化、副作用和回退信息。

第一版接入已有 Bug Report 导入及 Root 只读诊断，只比较同来源数据。不增加后台监控、自动修改系统、自动上传、跨设备排行榜、长期电池寿命预测或新的 Shizuku 采集链路。无 Key 时也能完整记录、比较和阅读本地结果；AI 解释是可选项。

成功标准：用户可以完成一次可恢复、可删除的验证记录；每个变化都有数值、单位、来源和窗口依据；不可比时明确说明原因；不把前后变化当作已证明的因果关系。

## 2. 现有代码边界

- `PowerDiagnosticSnapshot` 已保留来源状态、字段覆盖、按 UID 聚合的应用证据与本地结论，可作为摘要投影的输入。
- `BatteryDrainWindowEvidence` 只有电池运行时长、容量、耗电与实际/计算耗电标记，没有完整统计起止、重置标识或设备归属。
- `BatteryStatsEvidenceParser.parseDrainWindow` 读取的是 `Statistics since last charge` 区段。两次累计结果不能直接当成独立的调整前后样本。
- `sampledAtInstant` 是采集/解析流程传入的时间。对于导入报告，不得将其冒充报告生成时间，更不能推导统计窗口起点。
- 闹钟、任务、唤醒源等来源可能使用不同累计周期；同一份诊断中的所有字段不保证共享耗电窗口。
- 现有聊天加密归档仅保存显示消息。本功能使用独立归档，不向聊天归档塞诊断对象，也不改变旧归档格式。

因此“同来源”是必要而非充分条件。先实现明确的窗口与指标语义，再允许数值比较；未知必须保留，不能由用户勾选覆盖缺失的系统证据。

## 3. 方案选择

采用“结构化摘要 + 本地比较引擎 + 独立验证记录”。相比直接保存两段报告文字让模型比较，这能检查单位、统计范围与缺失值，且无需 Key。相比全天自动采样，用户主动操作的边界更清楚，也不引入后台保活和耗电负担。

数据流为：现有导入/采集流程 → 窗口元数据适配 → 白名单摘要投影 → 用户保存前/后样本 → 本地比较 → 双语结果展示 → 用户可选请求 AI 解释。

新逻辑独立分层，不整体重构 MainActivity、旧诊断规则或云端协议。

## 4. 用户流程与状态

1. 在成功诊断后点击“建立验证记录”，查看保存范围，选择目标应用组或整体耗电，填写使用场景，保存调整前摘要。
2. 填写一项调整、原设置/回退方式，并主动点击“已手动调整”。APA 保存确认时间，同时强调它没有读取或验证实际设置。
3. 用户再次主动导入/采集。保存后摘要前显示来源、统计窗口和与调整时间的关系；不可比仍可保存，但必须展示原因。
4. 查看逐指标前后值、可用差值、缺失原因，以及用户自行记录的通知延迟、功能异常等副作用。
5. 可记录“已手动回退”或结束记录。两者是用户声明，不表示 APA 执行了操作。删除记录会删除其全部摘要与备注。

持久状态：`BASELINE_SAVED`、`CHANGE_RECORDED`、`RETEST_SAVED`、`CLOSED`。`CLOSED` 另存结束原因：完成、用户回退、放弃。允许替换复测摘要，但不修改基线；修改调整内容或时间时清除旧复测及旧比较结果并要求确认。第一版每条记录最多一份基线、一项调整、一份复测，不实现多轮实验树。

没有诊断、没有来源或诊断无法生成有效白名单摘要时禁止建立记录；字段部分失败可以保存，并保留失败语义。已有记录独立于当前聊天与附件选择，清空聊天不删除验证记录，界面须说明这一点。

## 5. 数据契约

模型保持纯 Kotlin；稳定字符串 ID 用于归档，不能保存 enum.ordinal 或将展示文案作机器判断。

### VerificationRecord

- 随机记录 ID、schemaVersion、创建时间、最后修改时间、状态与结束原因。
- 本机作用域 ID：随机生成、仅本机存储；不是 Android ID、IMEI、序列号或远端身份。
- 基线摘要、可选调整、可选复测摘要；存储格式与比较规则版本独立记录。
- 标题最多 80 字符；调整说明、原设置/回退、使用场景与副作用备注各最多 500 字符。控制字符清理，不从备注解析可执行命令。

### DiagnosticVerificationSummary

- 来源 `BUGREPORT` / `ROOT`，摘要生成时间与原报告时间分开；报告时间可未知。
- 非唯一设备上下文：厂商、原始型号、API、系统构建版本（无法获得时为空）。导入报告优先读取报告自身的白名单元数据，不用当前手机身份替代报告归属。
- `deviceMatch`：Root 由当前本机采集链路建立归属；导入报告还需用户确认来自当前设备。型号匹配不证明是同一台手机，显示“用户确认”，缺少必要型号/系统元数据则不能进行数值比较。
- 来源结果与字段覆盖只保存类型化状态，不保存原始错误正文或原始诊断输出。
- 用户选择的使用场景枚举：待机、轻度交互、游戏、视频、其他；相似性确认、充电情况与额外调整声明分别保留 `YES/NO/UNKNOWN`。枚举相同不自动证明场景一致。
- 白名单数值：整体耗电、目标组估算耗电及前后台分项、前后台运行时长、唤醒锁时长、唤醒/闹钟/任务计数；每项附来源、单位、统计范围和可用状态。
- 最多保存目标组及按耗电排序的另外 19 组。包名集合排序后作为应用组键；UID 仅作展示线索，不作为跨样本身份。共享 UID 不拆分耗电，不按应用名匹配。
- 系统当前温度/thermalStatus 只作快照上下文，不推导窗口平均温度或温控改善。

### MetricWindow

- 指标所属来源、统计范围枚举、明确的统计开始/结束时间（可未知）、电池运行时长、充电状态、重置/累计周期标识（可未知）、值的实际/估算类别。
- 时间与周期只能来自对应白名单来源的明确元数据；不得用导入时间、文件名、文件修改时间或“报告时间减电池运行时长”补齐。
- 元数据解析只接受有测试样本支持的格式，重复冲突、非法时间、时区不明确时标为未知。按来源维护窗口，不把 batterystats 窗口赋给 alarm/jobs/wakeup_sources。
- 现有摘要兼容转换时新增字段一律未知。第一版不做累计值差分重建窗口、不执行统计重置命令。

## 6. 比较规则

`VerificationComparisonEngine` 是无 Android、无网络、无模型依赖的纯函数。输出总体门控原因及每个指标的结果，采用稳定原因码与双语格式器。

### 共同门槛

来源一致；本机作用域一致；设备上下文已按上述规则核对；型号/API/系统构建不能明确冲突。用户确认场景相似、无其他调整、相关阶段无充电；任一项否定或未知时禁止数值变化结论。

基线统计结束必须不晚于调整确认时间，复测统计开始必须不早于调整确认时间，两段统计窗口必须明确且互不重叠。导入顺序不证明时间顺序。重复摘要不得作为复测；指纹只基于规范化白名单数据、来源和明确窗口，不保存原文件哈希或内容。

每项单独要求：双方来源成功、字段已解析且未截断、数值有限且非负、单位和统计范围一致、值的实际/估算类别一致、目标包名组完全相同。缺失、组变化、字段不可用只阻断相应指标；不得把缺失解释为零或把应用未出现解释为停止运行。

### 时间与计算

- 双方有效统计窗口及电池运行时长至少 30 分钟，窗口更短显示“样本过短”。这是产品门槛，不是准确性认证。
- 双方电池运行时长比值须在 0.8..1.25 范围内。超出时展示原值，不生成改善判断；除以小时不能修复场景不匹配。
- 只对明确覆盖相应窗口的耗电计算 `mAh/电池运行小时`；保留实际/估算标签。只有容量也不能从电量百分比推算应用 mAh。
- 运行/唤醒锁时长以 `分钟/电池运行小时` 展示；计数以 `次/电池运行小时` 展示，仅在其来源提供匹配统计窗口时计算。前台进程时长不等于亮屏时长。
- 差值为复测速率减基线速率。相对变化为差值除以基线速率，基线为零时不计算百分比；显示“本次观察值增加/减少”，不显示“已节电 X%”。计算使用未舍入值，显示舍入不能反推精度。
- 没有误差模型或重复样本，不设置“显著改善”阈值，不输出确定性节电效果、唯一根因或健康度结论。不同指标可能方向相反，保留并列结果而非合成虚构总分。

结果类型：`CHANGE_OBSERVED`、`NO_NUMERIC_CHANGE`、`NOT_COMPARABLE`、`METRIC_UNAVAILABLE`。副作用是独立的用户反馈，不能被数值下降抵消。不生成自动“继续此设置”决定；显示用户下一步选择与已记录的回退说明。

特别限制：两份同一累计周期、窗口重叠的报告一律不做效果比较。第一版可以保存记录并指出需要独立、可核验的后续统计窗口；不得为了让界面有结果而放宽门槛。部分现有报告因元数据缺失只能并列展示，这是预期结果。

## 7. 存储与隐私

独立 `VerificationArchive`（纯 codec）与 `VerificationStore`（原子文件、加密、并发写入协调），Android 适配器使用 Keystore AES/GCM、独立 alias 和 noBackupFilesDir。可以复用成熟的小型加密原语，不扩大聊天归档的数据边界。

上限：20 条记录，单条明文编码最多 48 KiB，全归档最多 1 MiB；达到记录或字节上限时拒绝新增并提示删除旧记录，不静默淘汰活动记录。每条自创建起保留 30 天，修改不延长期限；打开、读取与写入时清理过期记录，不承诺应用未运行时立即清理。

schema 不支持、密钥不可用、校验失败、文件损坏时提示无法恢复，不用空数据冒充保存成功，不自动覆盖坏文件。明确用户确认“清空不可恢复记录”后才重建。原子保存失败保留旧归档；界面标明未保存，不能显示持久成功。删除与清空须处理排队写入，防止旧任务把已删记录写回。

保存的数据是经过最小化的敏感摘要，不是完全匿名：包名、时间及用户备注可能敏感。保存前展示范围；不保存原始报告、日志、Key、账号、唯一硬件标识或全量应用列表，不自动导出/联网。退出应用后可恢复记录，但不恢复原报告 URI 或原始输出。

## 8. AI 边界

新增独立的“解释本次对比”入口，不复用旧归因问题识别来猜用户意图。用户每次主动点击且确认发送范围后才联网；默认不把验证记录加入普通聊天请求或历史。

请求只包含当前记录的白名单前后指标、本地比较结果与原因、场景类型、实际能力等级。自由文本备注、原设置及回退文字默认不发送；用户可单独选择发送这些字段并预览。限制验证附件 16 KiB，超限阻止发送并解释原因，不能静默截断单位、窗口或门控结果。

用户备注和报告元数据作为不可信数据传入，不作为系统指令。模型必须服从本地不可比结论，不能补造窗口、把缺失补零、改变能力等级或声称已执行调整。输出固定区分观察变化、证据限制、副作用及下一步；不可比时解释补采需要，不能给出节电百分比。

第一版解释采用无历史的独立请求，不追加到普通云端历史或聊天归档，防止后来普通问题隐式携带验证数据。回答可会话内显示，错误/取消不改变验证状态；没有 Key 时继续显示本地比较结果。真实模型遵从度须另行评测，提示词或过滤单测不是准确率证明。

## 9. 模块与接入点

- `model/DiagnosticVerification.kt`：记录、摘要、窗口、指标、状态及原因码。
- `tool/DiagnosticWindowMetadataParser.kt`：只解析有证据支持的报告元数据，不负责比较。
- `agent/VerificationSummaryProjector.kt`：既有诊断到最小化结构，不依赖展示文字。
- `agent/VerificationComparisonEngine.kt`：共同/逐指标门控与计算。
- `agent/VerificationArchive.kt`、`VerificationStore.kt` 与 Android 存储适配器：独立版本、有界恢复及删除。
- 独立验证 ViewModel 与 Compose 面板：记录列表、调整表单、复测选择、对比与删除；现有诊断入口只增加明确操作，不把新流程堆进 Activity。
- 独立验证解释 payload/格式器：借用现有可取消传输接口，保持现有普通对话、健康/速率/归因契约不变。

先交付本地闭环与拒绝不可靠比较的能力，再接入可选 AI 解释；它们属于同一设计，但实施计划应分阶段验收，不同时建设长期监控或新权限平台。

## 10. 验收与测试

纯 Kotlin 单测必须先覆盖失败路径，再实现：

- 来源不一致、设备冲突、未知窗口、调整前后次序错误、重叠累计周期、重复摘要、场景/充电/额外调整未知或冲突全部拒绝效果判断。
- 已有累计两份报告不能被当成独立窗口；导入时间不能补报告时间；其他来源不能借用 batterystats 时间。
- 合成明确独立窗口可正确计算单位、差值和相对变化；零基线、缺失、负值、NaN/Infinity、越界时间、超短窗口及边界比例不崩溃。
- UID 改变但包名组相同不误判为新应用；共享 UID 组变化拒绝比较；条目缺失不补零。
- 某指标失败不吞掉其他已通过指标；相反方向的指标与副作用同时显示，不虚构总改善评分。
- schema/枚举稳定 ID、字节/条目/字段限制、30 天到期、未知版本、损坏、密钥失败、写入失败与删除竞态。
- 切页、重建、取消、进程恢复、重复点击、记录切换后旧任务完成均不能串写；修改调整后旧复测确实失效。
- 中英文窗口/数值/不可比理由一致；AI payload 不自动携带记录、默认不发送自由文本、不携带旧聊天历史，超限不静默截断。

仪器与实机验收单独记录：列表/表单/长结果滚动、大字体、小屏、离线全流程、Keystore 恢复/删除、真实报告缺失元数据提示；代表性 Root 与非 Root 设备验证元数据格式。不宣称在没有设备时已完成这些测试。

交付验收至少包含一组“不可比较的累计报告”与一组“有明确独立窗口的合成报告”。如果实机尚无可核验独立窗口，公开说明只完成保守门控和合成计算，不声称已验证真实优化效果。不要求真实模型调用作为本地闭环完成的前提。
