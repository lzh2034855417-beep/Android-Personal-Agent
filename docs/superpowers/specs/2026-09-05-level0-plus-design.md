# Level 0+ 普通用户设备报告设计

## 目标

让没有 Root、没有 Shizuku 的 Android 用户，也能将一份更完整且可解释的设备快照主动附带给 APA Agent。报告只读，不自动上传；只有用户发送在线问题并选择 Level 0 时才会交给选定模型。

## 数据范围

### 自动读取，无额外授权

- 电池：百分比、充电状态、充电方式、电流、剩余电量、剩余能量、温度、电压、电池健康状态、是否存在。
- 屏幕：物理分辨率、密度、当前刷新率、设备支持的最高刷新率。
- 系统与硬件：公开设备名称、Android 版本/API、安全补丁、SoC 名称（系统提供时）、支持的 ABI。
- 资源：总内存、可用内存、低内存标记、总存储、可用存储、已用比例。
- 设备评分：既有金银铜配置标；它只基于本机可读参数，不推断零件供应商或真实跑分。

每一项均可能因系统或厂商实现而缺失。缺失字段在报告中必须显示为“设备未提供”，不得以默认值伪造。

### 可选使用习惯，需要用户主动授权

- 当天亮屏时长。
- 当天最常用的若干应用及其前台使用时长。

APA 显示“授权使用情况”入口，跳转至 Android 系统的使用情况访问设置页。只有系统授予访问后，Level 0 报告才包含这些字段；未授权、拒绝或系统没有可用数据时，报告写明原因，不阻断其他基础数据。

不读取通讯录、照片、文件内容、精确位置、短信、通话记录或应用账号内容。

## 报告格式

Level 0 报告按以下固定分组输出，便于模型引用：

1. 本次采样与数据范围。
2. 设备与系统。
3. 屏幕体验。
4. 电池即时状态。
5. 内存与存储。
6. 可选使用习惯。

报告保留原始数值和单位，并附带“仅为本次快照”的限制。Agent 提示词要求：电池寿命、长期续航或性能趋势只能在存在足够数据时判断；否则说明还缺少什么数据。

## 组件与数据流

新增三个只读采集器：

- `DisplayInfoTool`：读取屏幕参数。
- 扩展 `BatteryTool`：读取标准广播与 `BatteryManager` 可提供的即时状态。
- `UsageStatsTool`：在系统授权后汇总当天亮屏时间与应用前台时长。

采集结果合入 `DeviceSnapshot` 和 `DeviceContext`。设备页展示关键摘要；`buildLevelReport("Level 0")` 输出全部结构化字段；云端请求继续使用既有“用户主动发送”流程。

## 错误与兼容

- Android 8.0（API 26）及以上保持可用。
- API 版本不支持的字段返回空值，不崩溃。
- 使用情况未授权时提供系统设置入口，不反复弹窗。
- 采集失败时保留已成功的其他分组，并以可读文字记录失败原因。

## 验证

- 为每个纯格式化/判定逻辑增加单元测试，覆盖已授权、未授权和字段缺失。
- 构建完整单元测试、Lint、Debug APK。
- 在连接真机上验证：未授权时报告可用；授权后使用习惯进入 Level 0 报告；设备页不因缺失字段出现异常。
