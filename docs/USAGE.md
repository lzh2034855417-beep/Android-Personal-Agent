# APA 使用指南

[返回首页](../README.md) · [隐私说明](PRIVACY.md) · [反馈问题](https://github.com/lzh2034855417-beep/Android-Personal-Agent/issues/new/choose)

本指南面向已发布的 0.3.1。不同系统的菜单名称和可读字段可能不同；后续版本以对应发布说明和应用内界面为准。

## 安装与更新

[Releases](https://github.com/lzh2034855417-beep/Android-Personal-Agent/releases/latest) → 展开 Assets → 下载正式版 `.apk` → 在手机上打开并安装。

`Source code` ZIP／TAR 是源码，不是安装包。Preview 是独立预览应用，和正式版的数据不互通。更新正式版优先覆盖安装；遇到签名冲突先反馈，不要为解决安装问题直接卸载已有应用。

## 先看设备信息

打开 APA → 设备 → 查看电池、内存、存储和硬件信息 → 需要时刷新硬件信息。

容量与厂商是不同字段：能读到容量，不代表系统一定提供厂商。导入本机系统报告可能补足字段；其他手机的报告不要用来覆盖本机硬件信息。无法识别的字段保持未知，不能据此认定硬件有问题。

## 导入系统报告

想看“哪个应用耗电多”，优先用手机生成的系统 Bug Report。无需 Root，通常也不需要解锁 Bootloader。

**生成报告：** APA → Agent → 怎么生成系统报告，先看适用于本机的提示。

部分小米／Redmi／POCO：系统拨号盘 → 输入 `*#*#284#*#*` → 等待完成 → 在通知或文件管理器中找到新生成的报告。

其他 Android，包括部分 vivo／iQOO／OPPO／一加：设置 → 搜索“开发者选项” → 查找“获取错误报告／提交错误报告” → 若存在则生成互动式报告 → 等待完成并保存文件。没有入口时查看系统帮助或反馈兼容情况；不要假定所有机型都有相同拨号码或文件路径。

**导入分析：** APA → Agent → 导入系统报告 → 选择刚生成的 ZIP／TXT → 等待读取与解析 → 查看系统耗电诊断 → 提问。

文件较大时需要等待，可根据界面提示取消。尽量保留原始 ZIP，不要只截取日志中的几行或选择旧日期的其他报告。

可以试问：“哪个应用最费电？”“今天耗电快吗？”“这个结果能说明后台异常吗？”本地与在线能力不同，无法判断时以结果给出的限制为准。

## 怎么理解耗电结果

- **窗口：** “自上次充满后”不等于今天全天，也不等于全程都在使用手机。
- **总量与后台：** 谁消耗最多和谁存在异常是两个问题；共享 UID 系统组不能直接拆给单个应用。
- **估算与实测：** 应用耗电通常是系统估算。上下限、缺失、截断或统计冲突都会影响结论。
- **续航外推：** 包含待机的平均值不能当成连续看视频时长或当前剩余续航。

兼容性按字段判断，不保证一个品牌的所有机型都读到相同内容。

## 只想粗略测掉电速度

Agent → 辅助：粗略续航测量 → 拔掉充电器并开始观察 → 正常使用至少 30 分钟 → 回到 APA 结束 → 如实确认期间是否充过电。

充电、时间太短或电量变化无效时，结果不能用于判断速度。恢复后的观察固定标为粗略。测量只能描述这一段的平均变化，不能定位哪个应用造成耗电。

## 可选在线 AI

设置 → 选择模型服务 → 填入自己的 API Key → 保存 → Agent → 检查所选报告和附加状态 → 发送。

模型服务的可用性和费用由服务商决定。配置模型不等于所有问题都能准确回答；维修、硬件健康或系统修改仍需独立核实。没有 Key 时可以使用本地查看、解析和有限规则解释。

## Root 与复测记录

已有 Root 的用户可在系统耗电诊断中主动开始只读采集。检测到管理器不代表已授权，单项不支持时可能只有部分结果。普通用户不必为了使用 APA 去 Root。

诊断后可打开“本地验证记录”，保存基线、记录自己做的一项调整与回退方式，再选择后续诊断复测。记录不自动操作系统；不同窗口或场景不一定可比，变化本身也不能证明是调整造成的。

请提供手机型号、Android 版本、APA 版本、是否 Root、操作步骤、期望与实际结果、脱敏截图。导入失败时先记录错误提示和文件大小。
